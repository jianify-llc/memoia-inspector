# Test deployment

This is a separate application on the existing Japan test host. It does not restart Memoia, PostgreSQL, Redis, or the host cloudflared service. The test hostname is `test-memoia-inspector.jianify.dev`; the container is reachable on the host only at `127.0.0.1:3001`. There is no online deployment in this repository yet.

## One-time operator setup

1. Review the host identity, available memory, port 3001, and the existing cloudflared service. Copy this directory's `compose.yml`, `deploy-inspector.sh`, and `runtime.env.example` to an operator-approved staging directory on the host. Run `sudo bash deploy-inspector.sh init-config`; this creates `/opt/memoia-inspector/.env` as root-owned mode 0600 and the deployment directory as mode 0700. Fill only the server `.env` with a dedicated Inspector Playground model key, base URL, and tested model. Do not commit that file or place it in an Actions artifact.
2. Configure the **existing host Tunnel** to route `test-memoia-inspector.jianify.dev` to `http://127.0.0.1:3001`. Create a Cloudflare Access self-hosted application protecting the **entire hostname**, allowing only the administrator's exact identity. Do this before exposing the route. Neither `wrangler.jsonc` nor the Inspector Compose manages the Tunnel.
3. This archived source cannot install the organization image produced by the current workflow. Keep Actions installation disabled until normal Release archival supplies the supported script. For reference only, the pre-existing legacy operator initialization accepted an old-namespace digest: `sudo bash deploy-inspector.sh init ghcr.io/jianify/memoia-inspector@sha256:<digest> <source-sha> <run-id>`. The script checks the image label, starts only Inspector, waits for its health check, and records the accepted digest. It does not validate the Access policy or the Playground model call; those need manual browser acceptance.
4. In the `test` GitHub Environment configure `DEPLOY_HOST`, `DEPLOY_PORT`, `DEPLOY_SSH_PRIVATE_KEY`, and `DEPLOY_SSH_KNOWN_HOSTS`. Actions connects directly as the existing `github` SSH user with a key dedicated to this repository and `sudo -n`; it does not use Cloudflare Access or the Lightsail default key. Confirm the host key from a trusted source. Keep repository variable `INSPECTOR_TEST_DEPLOY_ENABLED` unset/false while the archived installation entry is unsupported; after normal Release archival, Access, management operations and the real Playground flow still need separate acceptance.

The project URL/token entered in the UI are browser-session credentials. Inspector project switching clears the associated Playground user. Because the original API-key tab shows the project key, Access must cover every page and API route; origin port 3001 must not be exposed publicly. Memoia's own Bearer authentication remains independent.

## Daily update and recovery

Local `pnpm ci:local --mode quick` performs offline type, lint and business checks. Before Test push, `pnpm push:test` runs full checks against the outgoing commit and the pre-push remote Test baseline; explicit full without a baseline checks everything. Local source copies exclude dotenv files and Git credentials. Relevant tool changes select deployment/hook tests; the cloud does not rerun business validation.

`verify.yml` handles main PR candidates, merge queues and explicit validation by building the actual AMD64 Docker image without publication. Ordinary development, Test and release pushes do not trigger Actions. Test publication is explicitly manual: it builds AMD64 once, verifies immutable source identity and anonymous pulling, then retains the Test deployment gate. Stable release tags build AMD64 and ARM64 once per architecture on native runners, verify the assembled manifest and retain Online approval before installation. Dependencies and versions come from the manifest and lockfile; workflow scripts do not pin an extra Next patch version.

This archived main source still has only the legacy deployment modes and accepts the old image namespace. The workflow checks those concrete missing capabilities after checkout and stops before any SSH command; it does not install or switch the org image on a host. Normal Release source archival is required to restore the supported installation entry. This CI-only change does not update the deployment script or fabricate recovery coverage: main has no deployment transition test. Existing legacy operator commands and recovery behavior below remain unchanged.

The host records `current`, `previous`, and any unresolved `pending` candidate under `/opt/memoia-inspector/.deploy`. A failed first install has no previous version. Diagnose it before using `clear-pending <exact-source-sha>`; that command archives the pending record rather than silently retrying. For a later compatible version, use the explicit `restore-api <previous-image> <previous-source-sha> <new-run-id>` mode after reading `previous`. Image restoration does **not** undo management changes made against Memoia. Recheck Access and the real Playground flow after recovery.

Manual acceptance must cover: unauthorized Access denial; no direct public port 3001; correct and incorrect Memoia token; failed and successful user deletion/config update with read confirmation; project switch and credential loss; streaming chat, insert, flush, profile/event reads; container restart; memory/OOM. Automated local health checks do not establish these external boundaries. If no second compatible digest exists, cross-version update/restore remains unverified.
